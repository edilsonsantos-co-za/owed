The problem

Chasing money is draining, and one note doesn't fit every client.

For freelancers and small studios

The work is delivered, the invoice went out through PayPal, and three weeks later it is still unpaid. Do you nudge? How hard? Will a firm email cost you the client? Most people put it off, or send everyone the same polite note.

Clients are not all the same

One always pays two days early. Another pays seven weeks late, every time. The right reminder depends on the client's history, and that history is already sitting in PayPal.

How Owed works
01 · READ

PayPal invoices

Invoicing v2 and Transaction Search become a live receivables model: outstanding, overdue, aging, and when the cash should really land.

→
02 · DRAFT

Claude agents

A collections agent judges each client from their history and drafts a friendly, firm or final reminder, with a one-line reason.

→
03 · APPROVE

You decide

Every draft waits in Approvals. Edit, approve, and Owed sends a real PayPal reminder with a pay button. Or discard it.

How it's built

Agents that work as a team, and can't send on their own.

Dashboard and chatAG Studio embedded dashboards, themed to Owed, with a full-screen Customize editor. The Studio chat runs six agents in the browser.
Custom Claude adapterTranslates AG Studio's Agent Framework turns into streaming Claude calls (Anthropic Messages API, adaptive thinking), and Claude's stream back into AG-UI events.
Collections agentOwed's own agent, which Studio's built-in lead can delegate to. Tools: get_receivables, get_client_profile, draft_reminder, draft_invoice.
Morning briefA read-only Claude agent using the PayPal Agent Toolkit (list_invoices, search_invoices, list_transactions, get_merchant_insights).
PayPalInvoicing v2 (list, get, create, send, remind, record payment), Transaction Search.
AppNext.js 16, React, TypeScript, Tailwind CSS v4; Logto sign-in (OIDC + PKCE); Docker, deployed on every push.
Safety by construction

Approval is in the code, not the prompt.

Agent tools can only queue drafts. The only code path that calls PayPal's send or remind endpoints is the Approve button, which needs a signed-in person.

A prompt can be talked out of a rule; a missing tool can't. Every draft, approval and PayPal call is written to the Activity log with who did it: you, an agent, or the system.

The hosted demo also caps AI turns per visitor per day.

Try it

Live in a minute, with or without keys.

Hosted demo

Open owed.edilsonsantos.co.za. The landing page is public; create a free account (or use the test account in the Devpost testing notes) to open the dashboard. A first-visit walkthrough shows every page.

What to look at

  • Overview: KPIs, today's focus and the cash forecast
  • Clients: payment profiles and risk
  • Ask Owed: "Chase everyone more than 30 days late"
  • Approvals: edit a draft, approve or discard it
  • Activity: who did what

Run it locally

git clone https://github.com/edilsonsantos-co-za/owed
cd owed
npm install
npm run dev        # http://localhost:3000

With no keys it runs on a built-in demo business (seven clients, each with their own payment habits). Add keys in .env.local to switch on each part:

ANTHROPIC_API_KEYAsk Owed, the agents and the morning brief
PAYPAL_CLIENT_ID + SECRETlive sandbox data; then npm run seed
AG_STUDIO_LICENSE_KEYremoves the trial watermark
